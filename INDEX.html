Swagger/OpenAPI Visual Interface

🚀 Quick Start

Paso 1: Abre una terminal en backend/user-service
Paso 2: Ejecuta: .\gradlew.bat bootRun
Paso 3: Abre: http://localhost:8080/swagger-ui.html

¡Eso es todo! Ahora tienes una interfaz visual para probar todos tus endpoints.

🔗 Puntos de Acceso

Recurso URL Descripción
Swagger UI http://localhost:8080/swagger-ui.html Interfaz visual interactiva
OpenAPI Spec http://localhost:8080/v3/api-docs Especificación en JSON
H2 Console http://localhost:8080/h2-console Base de datos en memoria

📡 Endpoints Documentados

POST /api/usuarios/registro

Registra un nuevo usuario en el sistema

201 Created - Usuario registrado exitosamente

400 Bad Request - Email duplicado o datos inválidos

POST /api/usuarios/login

Autentica un usuario

200 OK - Login exitoso

401 Unauthorized - Credenciales inválidas

GET /api/usuarios/obtener/{id}

Obtiene un usuario por ID

200 OK - Usuario obtenido

404 Not Found - Usuario no encontrado

GET /api/usuarios/email/{email}

Obtiene un usuario por email

200 OK - Usuario obtenido

404 Not Found - Usuario no encontrado

GET /api/usuarios/listar

Obtiene la lista de todos los usuarios

200 OK - Lista obtenida

DELETE /api/usuarios/delete/{id}

Elimina un usuario

200 OK - Usuario eliminado

404 Not Found - Usuario no encontrado

🧪 Flujo de Prueba Recomendado

  1. Registra un usuario - POST /api/usuarios/registro
    POST /api/usuarios/registro { "nombreUsuario": "test_user", "email": "test@example.com", "contrasena": "password123" }
  2. Inicia sesión - POST /api/usuarios/login
  3. Obtén por ID - GET /api/usuarios/obtener/{id}
  4. Obtén por email - GET /api/usuarios/email/{email}
  5. Lista todos - GET /api/usuarios/listar
  6. Prueba errores - Usa datos inválidos o inexistentes
  7. Elimina usuario - DELETE /api/usuarios/delete/{id}

📊 Formato de Respuesta Estándar

Todas las respuestas siguen este formato JSON:

{ "success": boolean, // true para éxito, false para error "mensaje": string, // Descripción del resultado "datos": object|null // Datos de respuesta (null en errores) }

Ejemplo de Éxito:

{ "success": true, "mensaje": "Login exitoso", "datos": { "id": 1, "nombreUsuario": "juan_perez", "email": "juan@example.com", "activo": true, "creadoEn": "2026-01-15T10:30:00", "actualizadoEn": "2026-01-15T10:30:00" } }

Ejemplo de Error:

{ "success": false, "mensaje": "Nombre de usuario o contraseña incorrectos", "datos": null }

💡 Consejos para Usar Swagger

⚠️ Nota importante: La base de datos está en memoria (H2). Los datos se pierden al reiniciar la aplicación.

  • ✅ Comienza por el registro - Crea un usuario de prueba
  • ✅ Guarda el ID - Lo necesitarás para otras pruebas
  • ✅ Prueba casos de error - Intenta operaciones inválidas
  • ✅ Lee los mensajes - La API proporciona descripciones claras
  • ✅ Observa códigos HTTP - Ayudan a entender el resultado
